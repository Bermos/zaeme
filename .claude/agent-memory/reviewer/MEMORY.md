# Reviewer memory

Defects that reached `main` in Bermos/zaeme, and the blind spots that let them
through. Each is a question to ask of every diff. Dated, one line each.

The entries dated 2026-09-14 are the seed: they are read out of `CLAUDE.md`, the
commit history and the open issues at the moment this file was created, not out of a
review. Everything after them is earned.

## Defects that shipped

- 2026-09-14: A correlated sub-select in the domain was silently counting nothing (`3e6df6f`), and no test in CI touches a database (#14). Ask: does this query's correctness depend on a real Postgres, and did anything run it against one?
- 2026-09-14: A deploy-time guard keyed on the sha256 of the dump it guarded had to download the artifact in order to decide whether it needed the artifact — the artifact was deleted, the task failed, and the deploy stopped (Enterprise `30c429c`, same platform, same shape). Ask: can this guard short-circuit without fetching the thing it guards, and does it fail safe?
- 2026-09-14: A dry-run log cut the magic link in half (`95c3642`), so the only way into an instance with no mail transport was broken by a logging detail. Ask: is the credential this path emits intact and usable, and is there a test that reads it back?
- 2026-09-14: Timeline `PATCH` was lost in the Enterprise transplant (#8) — a route that existed and then quietly did not. Ask: does the screen that calls this route still have a route to call?
- 2026-09-14: A script's own header documented a sign-in recipe that no longer works (no `Origin` header — better-auth answers 403 — and "the newest `zaeme_verification` row" picks the wrong account); the PR that discovered it fixed its own copy and left the header (#49). Ask: did this change prove a committed instruction wrong, and was the instruction fixed where a human will read it?
- 2026-09-14: `HostTimelineCard.move()` reorders by two sequential PATCHes; a half-completed swap leaves two items on the SAME `sortOrder`, after which ↑/↓ computes a no-op forever and that pair can never be separated again (reproduced on a scratch Postgres; PR #50 copies the pattern to `/admin`, where there is no add/delete to recover with). Ask: is this multi-request write atomic, and what state does its half-failure leave the user in?
- 2026-09-14: `... is distinct from <new value>` in an UPDATE, added to keep `updated_at` still on rows that did not move, also removes those rows from the statement's LOCK set — so a concurrent writer's change to them survives the "atomic" renumber and two rows end up sharing a number anyway (PR #50, reproduced on Postgres 16; without the clause the same interleaving is a clean permutation). Ask: does this WHERE clause skip rows the statement's correctness depends on holding?
- 2026-09-14: A single-statement multi-row renumber deadlocks against itself — one `update … from (cte)` acquires row locks in plan order, and two concurrent copies deadlocked 7 times in 9000 statements over an 8-row list (PR #50). Ask: does this statement lock more than one row, in an order nothing pins?
- 2026-09-14: A write and the read that drives the UI must break ties on the SAME key. `applyTimelineItemMove` orders by `sort_order, starts_at, created_at, id`; every list query stops at `created_at` — so on a tied itinerary (the state the fix exists to repair) the user's first row is the server's last, ↓ is refused as off-the-end and the item silently jumps to the bottom (PR #50, reproduced). Ask: is the order the server computes the order the user was looking at?
- 2026-09-14: A shared guard typed `{ status: string }` throws away the schema's enum union, so any row with a `status` field compiles and a renamed status stops matching with typecheck green (`assertEventOpenToGuests`, #52). Ask: does this extraction widen a parameter's type past what the schema already proves?
- 2026-09-14: Re-inlining an extracted rule at its original call site and running the one boundary test proved a new assertion load-bearing in 40 seconds. Mutation-test structural tests; do not read them.

## Blind spots

- 2026-09-14: CI runs lint, typecheck and vitest and nothing else — no database, no server, no browser. `pnpm smoke:api` and `pnpm smoke:passkey` are the only things that execute the API and the passkey ceremony, and a human has to run them. Ask: which of the two does this PR need, and did it run?
- 2026-09-14: The contract test is a bijection over paths and methods only. Ask: is a field removed, a type narrowed, a status code changed — anything breaking for Enterprise's generated tools — while every test stays green?
- 2026-09-14: `test/api-boundary.test.ts` asserts where code lives and what it imports. Ask: is the gate this handler calls the right gate for its credential, which the test cannot see?
- 2026-09-14: Nothing notices when Enterprise's vendored copy of the spec drifts from this one (#11). Ask: does this PR oblige a follow-up in the other repository, and is it raised?
- 2026-09-14: The events domain has almost no coverage (#9). Ask: what would fail if this change were reverted in place, and is it a test?
- 2026-09-14: Merging deploys. Ask of every diff: what happens on the way up — a migration that cannot run twice, a startup that now needs an unset variable, a task that fails on the state the instance is really in?
- 2026-09-14: A field can be stored, typed and surfaced in the UI while no code consumes it — `events_expense.currency` shipped that way and produced a confidently wrong balance. Ask: does anything actually READ this column, and does the read do what the schema comment claims?
- 2026-09-14: `/api/v1` additions are the owner's call, not a refactor's (#8). Ask of any diff touching `docs/zaeme-api.openapi.yaml`: was exposing this to Enterprise's generated tools decided, or did it arrive as a side effect of building a feature for the guest surface?
- 2026-09-14: A smoke suite that SKIPS on unset env and still exits 0 can go green having proved a third less — `scripts/api-smoke.sh` is 106 checks with `S3_*` and both session cookies set and 78 without, and the `api` job asserts no count (#49). Ask: does the job fail when a GROUP skips, or only when a check fails?
- 2026-09-14: The `api` job migrates an EMPTY database once; the deploy runs the same `migrate` task against a database already at the previous release, every time (#49). Ask: does anything prove this migration applies to the state production is really in, and that a second run is a no-op?
- 2026-09-14: Anything a step writes to `$GITHUB_ENV` is reprinted in every later step's env group, so a session cookie minted there is in the build log unless `::add-mask::` went out first (#49). Ask: is the credential this job mints masked, or merely "not echoed"?
- 2026-09-14: The `api` job boots `.output/server/index.mjs` beside the full dev `node_modules` and with `INNGEST_EVENT_KEY` unset, so a runtime dependency declared as a devDependency still boots green and the whole event fan-out is never sent (#49). Ask: what does the built artifact resolve and reach in production that CI leaves standing beside it?
- 2026-09-14: A test that greps source proves a route EXISTS, not that it works: swapping the two same-typed `string` arguments of `applyTimelineItemUpdate(eventId, itemId)` keeps all 101 tests and `pnpm typecheck` green while every host timeline PATCH 404s (#50). Ask: does this diff thread two interchangeable ids through a new extraction, and does anything execute them?
- 2026-09-14: `server/domain/index.ts` re-exports the unguarded `*AsOwner` and `apply*` writes, and `test/api-boundary.test.ts` polices only `requireOwner`'s import site — a future host route could import an owner-scoped write and skip the gate with nothing failing. Ask: does this PR add an authorisation-free domain export, and is anything stopping a non-admin handler from calling it?
- 2026-09-14: A comment in the vendored contract can outlive the gap it describes — `docs/zaeme-api.openapi.yaml` still calls timeline editing a "KNOWN GAP, carried across the boundary unchanged" after #8 closed it on both human surfaces, and Enterprise reads that file. Ask: does closing this issue falsify a committed comment somebody else reads?
- 2026-09-14: Moving a write off the invite capability URL silently drops every check that rode on `resolveInviteToken` — revoked, expired, usage limit, draft/cancelled event (#52: a participant can still record money on a cancelled event through a revoked link's event). Ask of any route that changes credential: which checks belonged to the OLD credential, and does the new gate repeat them?
- 2026-09-14: A field added to a domain view reaches every surface that returns that view unshaped — `loadBudget`'s new `addedByEmail` went out over the invite capability URL because the guest budget is `loadBudget` verbatim, while `/api/v1` was safe only because `v1-shapes.ts` picks fields explicitly. Ask: which credentials can see this new field, not just the one it was built for?
- 2026-09-14: A new authorization primitive can be WIDER than the old one on the same operation — `assertParticipant` passes any planner role, so a `logistics` planner may write an expense on `/api/me` that `addExpenseAsPlanner` refuses them on `/api/host` and `/api/v1`. Ask: does the new gate agree with the existing gate on the same verb?
- 2026-09-14: A `v-if` on the invite page is part of the read surface. Dropping `complete` put the trip's expenses, balances and settlement in the SSR HTML of a generic link, for a visitor who has typed nothing. Ask of any condition removed on `app/pages/i/[token].vue`: who can now see this without identifying themselves?
- 2026-09-14: Smoke-run claims are checkable arithmetic: `grep -cE '^\s*(check|contains) ' scripts/api-smoke.sh` minus the assertions inside each `if [ -n "${…COOKIE:-}" ]`/`S3_BUCKET` block says which groups ran. #52's "102 passed" reconciled exactly (83 unconditional + 14 owner-cookie + 5 guest-cookie, S3 skipped) while its prose "nine new checks" was eight. Reconcile the total; the adjectives prove nothing.
- 2026-09-14: A structural boundary test is worth mutation-testing, not reading: add the forbidden import to a real handler, run the one file, revert. #52's new block caught all three injected violations in under a minute.
- 2026-09-14: An honesty check that falls back to the optimistic value fails open — `emailConfigured ?? true` on a failed `/api/setup/status` fetch promises a magic link on a dry-run instance. Ask of every "can this instance actually do it" question: which way does it answer when the question itself fails?
- 2026-09-14: #49's Postgres-backed `api` job does not close #14 by itself — a raw-SQL domain write is still proved by nothing unless a smoke check calls it. On PR #50, dropping the transposition, unscoping the renumber from one event to EVERY event, and hard-wiring the direction each left `pnpm test` (105) and eslint green, because the new tests grep for `row_number()` and count the word `update`. Ask: does anything EXECUTE this SQL, and would it fail if the SQL did the opposite?
- 2026-09-14: Hiding private data behind a `v-if` keyed on a client-resolved session hides it from the SSR MARKUP only — `useFetch` serialises the whole response into `__NUXT__` regardless, and the element reappears the instant the session resolves. Ask: does "not in the server HTML" mean "nobody sees it", or only "the crawler and the chat unfurler do not"?
- 2026-09-14: SSR privacy resting on a library's initial state is unpinned — better-auth's session atom is `isPending: true` until the browser fetches, and `useSession(useFetch)` returns `isPending: false`. A dependency bump or a one-word call-site change flips it and no test says so. Ask: which third-party default is this condition silently relying on?
- 2026-09-14: A smoke script's fire-and-forget teardown can be restoring nothing — `completed` has no outgoing transitions, so #52's status reset 409s into `/dev/null` and leaves the fixture in the wrong state for whatever is appended next. Ask: is every `> /dev/null` request in the suite actually legal, or just unchecked?
- 2026-09-14: A smoke `contains` over a FILTERED read can be satisfied by the unfiltered part of the same body — `/api/admin/audit` returns `{entries, summary}` and the summary carries `"surface":"me"` and `"actorKind":"participant"` whatever the query asked for, so #56's owner check passed with `entries: []` after every `me` row was relabelled (reproduced). Ask of every needle: does it appear anywhere OUTSIDE the part the filter controls?
- 2026-09-14: A polling helper is only as good as its needle. `audit_await` waits for a string the unfiltered summary already contains, so it returns on the first read and the write-then-read race it exists to close stays open for the assertion that follows (#56). Ask: would this poll ever loop?
- 2026-09-14: The label the edge computes and the answer the handler computes for the SAME request can disagree — a `logistics` planner who also RSVP'd is `participant` to `assertParticipant` and `planner` to the audit, because the recorder asks "is there a planner row" and the gate asks "what standing is this" (#56, reproduced on Postgres). Ask: does the middleware's version of the question match the handler's?
- 2026-09-14: A colour map keyed by an enum with `?? 'primary'` silently gives the NEXT value added the same badge as the one it was introduced to be told apart from; #56's boundary test pins the filter list and the select items but not the colours. Ask: does the test that says "every kind is covered" cover every place the kind is rendered?
